# 유물 재편성 (Relic Reshuffle)

[English](README.md) · **한국어**

전투에 진입할 때마다 **보유한 유물이 같은 희귀도의 다른 유물로 재편성되는** [슬레이 더 스파이어 2](https://store.steampowered.com/app/2868840/) 모드.

일곱 종류는 의도적으로 고정됩니다: 시작 유물과 서클릿, 고대의 존재·이벤트 유물(설정으로 포함 가능), 양초로 받은 밀랍 유물, 재련·정화에 골드를 쓴 유물, 다른 모드가 추가한 유물, 그리고 지금 캐릭터의 유물 풀 밖에 있는 유물.

희귀도는 보존됩니다 — 커먼은 다른 커먼으로, 레어는 다른 레어로. 유물 개수와 전체 파워 레벨은 그대로고, **무엇을** 들고 싸우는지만 매 전투 달라집니다. 재편성된 유물은 다음 전투에 들어갈 때까지 유지됩니다.

## 무엇이 바뀌나

| | |
|---|---|
| **시점** | 전투 방에 진입할 때 |
| **대상** | 교체 가능한 모든 유물을 같은 희귀도의 다른 유물로 1:1 교체 |
| **지속** | 다음 전투가 다시 재편성할 때까지 |
| **고정** | 시작 유물, 고대의 존재 유물, 스택형 유물, 강화된 유물 (스택형 외 전부 설정 가능) |

전투 시작 시 무엇이 무엇으로 바뀌었는지 짧게 표시된 뒤 사라집니다.

## 왜 희귀도를 보존하나

등급을 무시하고 굴리면 1막에서 레어 두 개를 쥐는 사람과 3막 보스 직전에 커먼 두 개를 쥐는 사람이 생깁니다. 둘 다 플레이어의 선택이 아니라 시드가 런을 결정한 것입니다. 희귀도를 보존하면 흔들림이 **파워**가 아니라 **정체성**에 걸리므로, 매 전투가 같은 난이도의 새 퍼즐이 됩니다.

규칙이 스스로를 설명한다는 장점도 있습니다. 유물 개수와 등급 분포가 불변이라 세이브/로드 후 맞춰야 할 것도, 따로 들고 있어야 할 "진짜 로드아웃"도 없습니다.

## 절대 하지 않는 것

- **1회성 보상 재발동.** 획득 시 효과를 한 번에 지급하는 유물(딸기, 망고, 판도라의 상자 등)은 재편성으로 지급되지 않으며, 교체는 게임의 조용한 인벤토리 경로를 쓰므로 `AfterObtained` 자체가 발동할 수 없습니다. 재편성으로 골드·최대 체력·포션 슬롯이 변하지 않습니다.
- **스택 삭제.** 스택형 유물은 교체 대상이 아니므로 전투 밖에서 쌓은 스택이 유지됩니다.
- **타 모드 유물 삭제.** 교체의 양쪽 모두 바닐라 유물로 제한됩니다.
- **얻을 수 없는 유물 지급.** 풀은 플레이어 자신의 것입니다 — 공용 풀 + 캐릭터 풀을 해금 상태로 거른, 게임이 실제 유물 보상을 만들 때 쓰는 바로 그 목록입니다.
- **런 시드 교란.** 재편성은 자체 RNG 스트림에서 파생되므로 보상·상점·맵은 같은 시드의 바닐라 런과 완전히 동일합니다.

## 설정

| 설정 | 기본값 | 비고 |
|---|---|---|
| 유물 재편성 사용 | 켬 | co-op에서는 **호스트** 설정이 모두에게 적용 |
| 시작 유물 고정 | 켬 | 시작 유물은 캐릭터의 일부 |
| 고대의 존재 유물 고정 | 켬 | 런을 규정하는 유물이라 비교할 동급이 없음 |
| 전투에 유용한 유물만 | 켬 | 상점·휴식처 전용 유물을 풀에서 빼 한 전투 내내 빈 슬롯이 되는 일을 막음 |
| 강화된 유물 고정 (Relic Forge) | 켬 | 강화 기록은 그 유물 인스턴스에 붙어 있어 재편성하면 사라짐 |
| 전투 시작 시 변경 내역 표시 | 켬 | 순수 표시 기능 — 항상 본인 설정이 적용 |

**교체 비율 슬라이더는 일부러 넣지 않았습니다.** "일부만 바뀐다"는 매 전투 인벤토리를 대조해 무엇이 바뀌었는지 찾게 만들지만, "전부 바뀐다"는 한 번 읽고 끝나는 규칙입니다. 고정 대상은 무작위 일부가 아니라 **카테고리**로 정합니다.

## 멀티플레이

지원합니다. 유물 효과는 양쪽 기기에서 lockstep으로 시뮬레이션되므로 두 피어가 같은 답에 도달해야 하는데, **패킷 교환 없이** 해냅니다 — 각 피어가 이미 서로 합의하고 있는 값(런 시드, 층, 플레이어 NetId, 슬롯, 원본 유물)에서 같은 재편성을 파생합니다. 호스트가 설정을 브로드캐스트해 양쪽이 동일한 규칙으로 파생하도록 맞춥니다.

2-인스턴스 수렴 테스트로 검증했습니다: 재편성 전후 두 플레이어의 유물 목록에 양 피어가 모두 합의했고, 모든 교체에서 희귀도가 보존됐으며, 상태 발산이나 체크섬 불일치가 기록되지 않았습니다.

## 세이브/로드와 전투 리셋

- **껐다 켜도** 같은 유물이 돌아옵니다. 게임은 전투 중에 저장하지 않으므로, 로드하면 같은 입력에서 같은 파생이 재생됩니다.
- **같은 전투에 다시 들어가도**(전투 리셋·되돌리기 모드) 재편성되지 **않습니다**. 가드가 방 객체가 아니라 층 기준이라, 전투를 되돌려도 유물이 다시 섞이지 않습니다.

## 호환성

- **[Relic Forge](https://github.com/ing-gom/sts2-relic-forge)** — 강화된 유물은 기본적으로 고정되고, 숨겨진 동반 유물은 건드리지 않습니다.
- 다른 모드가 추가한 유물은 전혀 손대지 않습니다.

## 빌드

`Sts2.ModKit`이 형제 디렉터리(`..\Sts2.ModKit\build\Sts2.ModKit.props`)에 있어야 하고, `GodotPath`를 제공하는 로컬 `Directory.Build.props`가 필요합니다. 배포용은 `Release`로 빌드하세요 — 셀프테스트 파일은 Release에서 제거되므로 남아 있던 테스트 플래그가 실제 런에 영향을 줄 수 없습니다.
